unhaine — Project Overview
비즈니스 문제를 이해하고, 해결 방법을 설계하며, 직접 구현하는 사람을 소개하는 인터랙티브 개인 웹사이트.

- 프로젝트명: unhaine
- 웹사이트: unhaine.com
- 프로젝트 유형: 개인 소개 · 커리어 · 포트폴리오 · AI 기반 탐색 인터페이스
- 문서 상태: 기획 초안 (2026-11-16)

1. 프로젝트 배경
unhaine은 경력과 프로젝트를 정리하고, 다음 커리어 기회를 향해 나아가기 위한 개인 웹사이트다. 단순한 온라인 이력서나 작품 전시 페이지를 넘어서, 방문자가 어떤 문제를 다뤄왔는지, 어떤 판단을 통해 해결했는지, 앞으로 어떤 영역에서 일하고 싶은지를 이해할 수 있도록 구성한다.

2. 핵심 목표
1. 사람을 소개한다. 이력, 학습, 역량, 가치관, 커리어 방향을 일관되게 전달한다.
2. 실제 작업을 증명한다. 프로젝트 결과뿐 아니라 문제 정의, 제약, 의사결정, 구현 과정, 성과와 한계를 함께 제시한다.
3. 정보를 쉽게 탐색하게 한다. 일반적인 페이지 탐색과 자연어 기반 AI 질의응답을 함께 제공한다.
4. 사이트 자체를 프로젝트로 만든다. 콘텐츠 구조화, AI 통합, 빠른 응답, 배포·운영 경험을 실증하는 장으로 활용한다.

[Ask unhaine] — 특정 페이지 소속이 아닌 전체 사이트 공통 AI 인터페이스
위 경로는 권장 URL 설계다. 초기 정적 HTML 프로토타입의 실제 파일명/링크와 다를 수 있다.

Main
웹사이트의 첫인상과 탐색 시작점이다. 핵심 메시지(Hero), 간단한 소개, 대표 프로젝트, Ask Unhaine 진입점, 연락 유도 영역으로 구성한다. 모든 상세 정보를 메인에 복제하지 않고 해당 페이지로 연결한다.

About
'어떤 사람인가'에 집중한다.
- Career: 경력과 맡은 역할, 직무 변화의 흐름
- Education: 학력, AI 관련 교육과 학습 과정
- Values: 목표 지향성, 책임감, 협업, 근거에 따른 판단 수정 등 실제 행동에 기반한 업무 가치관

Portfolio
카탈로그 → 개별 상세 사례의 2단계 구조를 사용한다. 카탈로그는 프로젝트별 큰 미리보기 이미지, 프로젝트명, 짧은 소개, 분류 및 상세 링크를 위에서 아래로 나열한다. 복잡한 필터링은 초기 필수 기능이 아니다.

초기 공개 대상 프로젝트는 다음 두 가지다.
- Billain: 반복적인 청구/빌링 업무를 웹 기반으로 자동화한 프로젝트. 문제의 발견, 업무 규칙과 데이터 구조 설계, 구현 및 운영 성과를 다룬다.
- kata: 에이전트 실행 방식과 오케스트레이션을 탐구하는 KATA 및 실행 과정·상태 시각화 프론트엔드 KIRI에 대한 설계·실험을 다룬다. 실제 완료 범위와 예정 범위를 구분해 서술한다.

프로젝트 상세 페이지 공통 흐름은 Overview → Problem → Constraints & Decisions → Solution → Outcome → Reflection을 기준으로 하되, 사례별 특성에 맞게 조정한다. 성과, 기여 범위, 현재 개발 상태를 과장하지 않는다.

Contact
빠르게 연락할 수 있도록 이메일을 중심에 두고 GitHub, LinkedIn 등 실제 운영하는 외부 채널 및 이력서 접근 링크를 제공한다. 초기에는 서버 기반 문의 양식을 필수로 두지 않는다.

4. Ask Unhaine — 전역 AI 인터페이스 (구현범위에서 제외)
Ask Unhaine은 Main의 부속 기능이 아니라 웹사이트 전반을 포괄하는 공통 탐색 수단이다.

unhaine에는 두 가지 탐색 방식이 공존한다.
- Web UI: 방문자가 메뉴와 페이지를 직접 탐색
- AI UI: 방문자가 자연어로 질문하고 관련 답변·콘텐츠·에셋을 탐색
두 방식은 서로 다른 사실을 유지하는 것이 아니라 동일한 콘텐츠 원본을 소비해야 한다.

컨텍스트 구성
구분	역할
Knowledge Context	프로필, 경력, 교육, 역량, 가치관, 프로젝트 등 확정된 정보
Page Context	방문자가 현재 열람 중인 페이지 또는 프로젝트
Conversation Context	현재 대화의 질문, 지시 대상, 후속 맥락
Asset Context	답변과 함께 제공할 사전 준비된 이미지, 프로젝트 화면, 링크, 데모 등


예를 들어 Billain 상세 페이지에서 '이 프로젝트에서 가장 어려웠던 점은?'이라고 질문하면 현재 페이지를 우선적인 단서로 활용하되, 답변에 필요할 경우 다른 관련 정보도 참조할 수 있어야 한다.

초기 구현 방향
1. 공통 콘텐츠 소스: 웹페이지 표시용 텍스트와 AI 응답용 지식이 분리되어 불일치하지 않도록 콘텐츠를 구조화한다.
2. 질문 라우팅: 다양한 표현의 질문을 관련 주제와 데이터에 연결한다.
3. 사전 정의된 에셋: 이미 준비된 화면/링크/자료를 우선 활용하여 응답 속도와 일관성을 높인다.
4. 하이브리드 응답: 간단한 질문은 가벼운 검색·판단 경로로 처리하고 복잡한 요청에 한해 더 큰 모델이나 kata 연계를 검토한다.
5. 전역 접근성: Main에서는 크게 노출하고, 다른 페이지에서는 공통 채팅 진입점으로 접근한다.
6. 사실 경계: 방문자의 질문이나 AI의 추측을 공식 경력·프로젝트 정보로 자동 등록하지 않는다. 공개되지 않은 내부 데이터나 개인정보도 노출하지 않는다.
kata 연계, 실제 생성형 응답, 검색·라우팅 최적화는 설계 방향이다. 정적 HTML 시안에 데모 채팅이 있더라도 실제 AI 연결이나 완성된 kata 통합을 의미하지 않는다.

5. 디자인 및 UX 원칙
- 간결한 정보 구조: 최상위 메뉴는 Main / About / Portfolio / Contact 네 가지를 유지한다.
- 명확한 정보 위계: 첫 화면은 핵심 정체성과 대표 작업을 보여주고, 상세 정보는 하위 페이지에서 제시한다.
- 콘텐츠 우선: 보여주기 위한 효과보다 실제 프로젝트 경험과 설명의 명료함을 우선한다.
- 스크롤 기반 카탈로그: Portfolio는 위에서 아래로 프로젝트를 순서대로 확인하게 한다.
- 양방향 탐색: AI를 사용하지 않아도 모든 핵심 정보를 읽을 수 있어야 한다.
- 반응형·접근성: 모바일과 데스크톱 모두에서 탐색, 대비, 키보드 접근 등을 고려한다.
- 빠른 반응: 사전 준비 콘텐츠와 자산을 활용하고 불필요한 AI 호출을 줄인다.
시각적 테마, 색상, 폰트, 모션은 추후 시안 검토를 통해 확정한다.

6. 구축 단계
Phase 1 — 정적 사이트
- 전체 페이지 및 메뉴 연결
- About 4개 하위 영역 작성
- Portfolio 카탈로그와 Billain / KATA 상세 페이지 작성
- Contact 정보 및 공통 Footer 구성
- 실제 이미지·텍스트·외부 링크 교체

Phase 2 — 공통 콘텐츠 데이터
- 프로젝트·경력·학력 등 데이터 구조 정의
- 웹페이지와 AI가 같은 자료를 참조하도록 정리
- 콘텐츠 수정 시 노출 정보의 일관성 검증

Phase 3 — Ask Unhaine
- 모든 페이지에서 열리는 채팅 UI
- 질문 분류 및 관련 컨텍스트 조회
- 현재 페이지 맥락 반영
- 준비된 에셋·페이지 링크 반환
- 모호한 질문·정보 부재·오답 방지 테스트

Phase 4 — 운영 및 고도화
- KATA 연계 가능성 검증
- 응답 시간·비용·검색 품질 관찰
- 질문 패턴 분석 및 콘텐츠 보강
- 배포, 성능, 접근성, 개인정보 보호 개선
