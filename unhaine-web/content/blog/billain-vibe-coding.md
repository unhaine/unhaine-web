## 1. 시작하며

2026년 2월부터 바이브코딩으로 Billain이라는 업무용 웹 서비스를 개발하기 시작했습니다.

개발을 전문적으로 배운 사람이 아니었기에 시행착오도 많았습니다. 프로젝트를 몇 번이나 갈아엎었고, 예상하지 못했던 문제에 시간을 쏟기도 했습니다.

그래도 결국 실제 업무에서 사용하는 서비스를 만들 수 있었습니다.

그 과정에서 바이브코딩의 가능성에 감탄하기도 했고, 한계를 체감하기도 했습니다.

이번에는 직접 개발하면서 느낀 몇 가지 이야기를 해볼까 합니다.

## 2. 바이브코딩에도 공부가 필요했습니다

처음 바이브코딩을 접했을 때 가장 놀라웠던 건 그럴듯한 결과물이 만들어지는 속도였습니다.

몇 가지 요구사항을 전달하면 순식간에 화면과 기능이 만들어졌습니다. 처음에는 이 정도면 누구나 개발할 수 있겠다는 생각도 들었습니다.

그런데 프로젝트가 커질수록 문제가 생겼습니다.

겉보기에는 멀쩡한데 내부 구조는 엉망인 경우가 많았습니다. 기능을 추가할 때마다 다른 부분에 문제가 생기기도 했고, 코드를 어떻게 관리해야 할지 몰라 프로젝트를 여러 번 다시 시작했습니다.

그러면서 아키텍처, 데이터베이스 설계, 요구사항 명세 같은 기본적인 개발 지식의 필요성을 절감했습니다.

AI에게 어떻게 일을 지시하고, 결과물을 검증하며, 프로젝트의 맥락을 유지할지도 공부해야 했습니다.

**코드를 직접 작성하지 않아도 된다는 것과, 개발을 몰라도 된다는 것은 전혀 다른 이야기였습니다.**

## 3. 토큰은 언제나 부족했습니다

바이브코딩을 시작하면서 예상하지 못한 지출이 생겼습니다. 바로 AI 구독료입니다.

한때는 카카오톡을 통해 월 300달러짜리 요금제를 6개월간 총 3만 원에 이용할 기회가 있었습니다.

그 기간이 끝난 뒤에는 월 100달러짜리 요금제를 직접 결제하면서 사용하고 있습니다.

문제는 요금제를 올려도 사용량이 늘 부족하게 느껴진다는 점이었습니다.

작업을 진행하다 보면 대화가 길어지고, 여러 파일을 검토하고, 오류를 수정하는 과정에서 토큰 사용량이 빠르게 늘어났습니다.

특히 프로젝트 규모가 커질수록 AI에게 전달해야 하는 맥락도 많아졌습니다.

덕분에 단순히 좋은 모델을 사용하는 것뿐 아니라, 작업을 어떻게 나누고 필요한 정보를 어떻게 전달할지도 고민하게 됐습니다.

## 4. 몇 달 사이에 세상이 달라졌습니다

개발을 시작한 이후 짧은 시간 동안에도 AI 모델과 개발 도구는 눈에 띄게 발전했습니다.

특히 인상적이었던 건 과거에는 여러 차례 수정해야 했던 작업을 새로운 모델은 훨씬 수월하게 처리하는 경우가 늘었다는 점입니다.

프로젝트를 여러 번 갈아엎은 데에는 제 설계 역량이 부족했던 이유도 있지만, 새롭게 등장한 도구와 모델을 활용하면서 이전보다 나은 결과물을 만들 수 있었던 점도 있습니다.

가끔은 과거에 며칠씩 고생하며 구현했던 기능보다 새로 만든 기능의 완성도가 더 높아 당황스럽기도 했습니다.

그렇게 개발을 계속하면서 한 가지 생각이 들었습니다.

**이제 무언가를 만들 수 있다는 사실만으로는 큰 차별점이 되기 어렵겠구나.**

AI가 만들어낼 수 있는 결과물의 수준이 빠르게 높아지는 만큼, 무엇을 만들고 어떻게 활용할 것인지가 더욱 중요해질 것 같았습니다.

## 5. 개발보다 운영이 더 어려웠습니다

Billain을 만들면서 가장 크게 느낀 점은 **프로토타입 개발이 전체 과정에서 차지하는 비중이 이제는 아주 작아졌다는 사실**이었습니다.

화면이 나오고 기능이 동작하는 것까지는 생각보다 빠르게 도달할 수 있었습니다.

하지만 실제 사용자가 업무에 활용할 수준으로 완성도를 높이는 것은 전혀 다른 문제였습니다.

데이터가 정확하게 처리되는지 검증해야 했고, 예상하지 못한 예외 상황을 처리해야 했습니다. 사용자가 실수하더라도 문제가 발생하지 않도록 고민해야 했고, 운영 중 발견되는 오류도 계속 수정해야 했습니다.

특히 청구 금액을 다루는 시스템이다 보니 작은 오류도 가볍게 넘길 수 없었습니다.

그 과정에서 프로토타입과 실제 서비스 사이에 생각보다 큰 거리가 있다는 사실을 알게 됐습니다.

이제는 새로운 서비스를 볼 때도 기능 자체만큼이나 안정성, 유지보수, 운영 방식에 관심을 갖게 됩니다.

**만드는 것은 점점 쉬워지고 있지만, 제대로 작동하게 만들고 계속 운영하는 일은 여전히 어렵습니다.**

그리고 아마 앞으로 더 많이 공부해야 할 부분도 그쪽일 것 같습니다.
