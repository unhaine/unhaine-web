만들고 있는데, 아직 어렵습니다 — kata

AI 에이전트와 함께 일하는 방식을 직접 설계해 보는 이야기.

1. 무슨 엔지니어링이 이렇게 많을까요?

생성형 AI가 발전하면서 이를 활용하는 방법론도 빠르게 변화하고 있습니다.

처음에는 모델에 어떤 지시를 내릴 것인지 고민하는 프롬프트 엔지니어링이 주목받았습니다. 이후에는 필요한 정보를 적절한 시점에 제공하고 관리하는 컨텍스트 엔지니어링이 강조되기 시작했습니다.

최근에는 도구와 실행 환경, 검증 체계를 설계하는 하네스 엔지니어링부터 에이전트의 반복적인 실행 과정을 다루는 루프 엔지니어링까지 이야기되고 있습니다.

프롬프트, 컨텍스트, 하네스, 루프.

무슨 엔지니어링이 이렇게 많은 걸까요?

물론 각각이 완전히 독립된 분야는 아닙니다. 서로 겹치는 부분도 많고, 새로운 이름으로 기존의 개념을 설명하는 경우도 있습니다.

하지만 결국 지향하는 바는 비슷하다고 생각합니다. 바로 AI가 사용자가 원하는 일을, 원하는 방식으로, 제대로 끝내주었으면 좋겠다는 것입니다.

2. 그래서 직접 만들어보기로 했습니다

에이전트를 활용하는 다양한 도구와 방법론이 등장하면서 Superpowers, gstack, Herdr 등 여러 프로젝트를 살펴보고 사용해 보았습니다.

그런데 솔직히 기대했던 만큼의 차이를 체감하지는 못했습니다.

제가 제대로 활용하지 못한 것인지, 제 작업 방식과 맞지 않았던 것인지, 아니면 아직 효과를 판단할 만큼 충분히 경험하지 못한 것인지는 모르겠습니다.

그러다 문득 이런 생각이 들었습니다.

'이왕 이렇게 된 거, 직접 만들어보면서 공부해 볼까?'

이미 잘 만들어진 도구들이 많은데 굳이 또 하나를 만드는 것이 비효율적일 수도 있습니다.

하지만 직접 설계하고 구현해 보면 그동안 이해하지 못했던 부분을 조금 더 깊이 알 수 있을 것 같았습니다.

그렇게 kata라는 개인 프로젝트를 시작했습니다.

3. 프로젝트의 맥락은 어디에 남을까요?

에이전트와 긴 프로젝트를 진행하면서 가장 불편했던 점 중 하나는 작업의 연속성이었습니다.

하나의 대화 세션에서 오랫동안 작업하다 새로운 세션을 시작하면, 이전까지 어떤 결정을 내렸고 왜 그런 구조를 선택했는지 전달하기 어려웠습니다.

그렇다고 모든 대화와 작업 기록을 새로운 세션에 전달하는 것도 비효율적이었습니다.

그래서 kata에서는 작업 환경을 네 가지 영역으로 구분하는 구조를 구상했습니다.

  • Project — 프로젝트: 목표와 진행 상황, 작업 이력과 의사결정 기록을 관리합니다. 새로운 세션에서도 지금까지의 맥락을 파악할 수 있도록 하는 것이 목적입니다.
  • Harness — 하네스: 에이전트의 역할과 작업 지침, 실행 절차, 검증 기준 등 작업 방식을 관리합니다.
  • Resources — 리소스: 여러 프로젝트에서 공통으로 사용할 수 있는 도구, 코드, 템플릿 등의 재사용 자산을 관리합니다.
  • References — 레퍼런스: 작업의 근거가 되는 문서와 기술 자료, 외부 정보를 관리합니다.

이렇게 구분하면 새로운 세션이 시작되더라도 프로젝트의 상태와 작업 방식, 필요한 자산과 참고 자료를 체계적으로 전달할 수 있지 않을까 생각했습니다.

대화를 전부 기억하게 만드는 것보다, 작업을 이어가는 데 필요한 맥락을 관리하는 것.

이것이 kata 설계의 출발점입니다.

4. 만들고 있는데, 아직 어렵습니다

구상한 구조를 바탕으로 실제 개발을 진행하고 있지만, 아직 만족스러운 결과를 얻지는 못하고 있습니다.

기존 GitHub 프로젝트들을 참고 자료로 제공하고, 원하는 구조와 동작 방식을 설명하면서 구현을 시도하고 있습니다.

그런데 생각만큼 쉽지 않습니다.

설계 의도를 충분히 전달했다고 생각해도 결과물이 기대와 다르게 나오거나, 특정 기능을 수정하면서 전체 구조가 복잡해지는 경우도 있습니다.

무엇보다 어려운 것은 문제가 어디에 있는지 판단하는 일입니다.

모델의 한계인지, 지시가 부족했던 것인지, 아니면 애초에 제 설계가 적절하지 않았던 것인지 구분하기 어려울 때도 있습니다.

어쩌면 여러 방법론을 사용하면서 효과를 크게 느끼지 못했던 이유도 여기에 있을지 모르겠습니다.

아직 무엇이 더 나은 방식인지 판단할 만큼 충분한 경험과 기준을 갖추지 못한 것일 수도 있으니까요.

AI가 원하는 대로 일하지 않는다고 생각했는데, 정작 제가 원하는 것이 무엇인지 정확히 정의하는 일부터 쉽지 않았습니다.

5. 도구는 바뀌어도 남아야 하는 것들

한편으로는 이런 의문도 있을 것 같습니다.

AI 모델과 에이전트 하네스가 계속 발전하고 있는데, 굳이 새로운 시스템을 만들 필요가 있을까요?

사실 저도 그렇게 생각합니다.

kata는 기존 에이전트 하네스와 경쟁하거나 이를 대체하기 위해 만드는 시스템이 아닙니다. 오히려 더 뛰어난 도구와 방법론이 등장한다면 적극적으로 활용하고 싶습니다.

제가 관심을 둔 것은 도구 자체보다 그 도구를 사용하며 쌓이는 경험과 작업의 결과였습니다.

어떤 도구를 사용하더라도 이전 프로젝트에서 얻은 지식과 작업 방식을 자연스럽게 이어갈 수 있다면 어떨까 싶었습니다.

아직은 그 가능성을 직접 만들어보며 확인하는 중입니다.

앞으로 어떤 형태로 발전할지는 모르겠지만, 그 과정에서 또 새로운 것을 배우게 되지 않을까 기대하고 있습니다.
